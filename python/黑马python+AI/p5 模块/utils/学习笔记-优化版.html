普通包初始化与公开接口（P76）

原始代码：init.py

# 描述包信息
__version__ = "1.0.0"
__author__ = "kunme1"

__all__ = ["my_fun", "my_var"]

当前仅声明元数据和__all__，没有 from . import my_fun, my_var。新进程中 import utils 先执行init；此时不保证utils.my_fun存在。随后 from utils import * 可以依据清单加载现有子模块，再把模块名绑定给调用方。不要把“只写all能星号导入”错说成“只写all已提前导入所有子模块”。

建议改写：init-优化版.py

可读性／接口明确化：新增显式相对导入，明确包导出来源，保留metadata和all。文件名保留 __init__-优化版.py 供对照，不会自动替代真正init；若采用，核心为在原init元数据前添加 from . import my_fun, my_var。直接运行对照文件走另一分支以便独立运行。完整初始化方案在临时副本采用为init后验证，不改原包。

"""来源：__init__.py；配套：学习笔记-优化版.md。
整理日期：2026-11-24；原始文件保留。
"""

# 原__init__.py仅写元数据和__all__，并未显式绑定两个子模块。
# 供采用的初始化片段如下：放回真正的__init__.py时，__package__为utils，走相对导入。
# 新知识：from . import引用当前包，直接import utils后即可访问已加载子模块；
# 行为变化：普通import utils也会提前加载子模块，不再等到star或明确导入时才加载。
if __package__:
    from . import my_fun, my_var
else:
    # 本文件名带“-优化版”，Python不会把它当初始化文件自动执行。
    # 为便于直接运行对照，按__file__补入p5目录后导入原utils的两个子模块。
    # 不覆盖原__init__.py；不修改持久环境配置，且不产生打印。
    from pathlib import Path
    import sys
    module_root = str(Path(__file__).resolve().parents[1])
    if module_root not in sys.path:
        sys.path.insert(0, module_root)
    from utils import my_fun, my_var

__version__ = "1.0.0"
__author__ = "kunme1"  # 原作者数据保留，不作为英文拼写错误改写。
__all__ = ["my_fun", "my_var"]

静态告警处理：记录中的 reportUnsupportedDunderAll 是工具诊断，不能反推运行时import必错。优先让导出显式可见；若仅想保留合法动态机制，可考虑针对该行抑制已核实的诊断，但本轮没有修改配置，也没有确认当前Pylance界面告警是否消失。历史曾加显式导入通过界面的记录，不等于当前文件仍有相同改动。

# 函数
# *： 字符串重复输出
def log_separator1():

    print("+" * 30)


def log_separator3():
    print("#" * 30)


def log_separator4():
    print("*" * 30)

四个函数按定义字符重复30次并print；没有顶层调用，导入不输出。第1行含空格，最终长度60字符，其他符号行30字符；没有把它们误当同一长度。对短演示无须抽象成复杂工具。

PI、NAME为常量命名约定，值并非由Python强制不可更改。NAME="kunme1"是样本数据，不纠正为别的英文词。

补充（参考课程资料）与纠正：普通包的init可为空；命名空间包例外不能省略不讲。包无all时star不自动扫描文件系统，不意味着star语句必报错；它只带出当时已有公开名字。包内 from . import my_fun 才是相对导入；外部 from utils import my_fun 是绝对导入。参照官方模块与包说明，并对当前纯控制台工具在临时副本独立验证。

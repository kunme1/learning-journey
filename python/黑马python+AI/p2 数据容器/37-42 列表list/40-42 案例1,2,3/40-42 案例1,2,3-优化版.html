案例2：合并与去重

图片文字版（来源：image-2.png）：

合并两个列表的元素，并去除重复。图中原始数据：

num_list1 = [19, 23, 54, 64, 875, 20, 109, 232, 123, 54]
num_list2 = [55, 80, 72, 35, 60, 123, 54, 29, 91]

源文件第27—88行比较4种写法：按索引append、直接遍历元素append、[list1,list2]解包、list1+list2。前两种会修改num_list1，后两种创建新列表；不能说所有方式对输入对象都没有影响。若取消全部注释连着执行，前一种修改会影响后续示例，因此应独立比较。

图片文字版（来源：image-3.png）：

小结：+可直接合并；*可解包元素；元素 in 列表判断是否存在，True存在，False不存在。原图代码：

num_list1 = [19, 23, 54, 64, 875, 20, 109, 232, 123, 54]
num_list2 = [55, 80, 72, 35, 60, 123, 54, 29, 91]
num_list = num_list1 + num_list2
num_list = [*num_list1, *num_list2]
new_list = []
for num in num_list:
    if num not in new_list:
        new_list.append(num)

补充：not in先查新列表是否已有这个值，再append，保留第一次出现顺序。对于n项、均不同等情况，列表成员查找反复线性扫描，累计可能O(n²)；小练习数据很少，不必只为“高级”换写法。

前瞻优化：数据可哈希（本题为整数）时，用set记录是否见过，列表保存输出顺序，平均情况下查找工作量改善到O(n)级，额外使用O(n)空间；哈希碰撞等使最坏情况不具这个保证。完整独立示例：

number_list1 = [19, 23, 54, 64, 875, 20, 109, 232, 123, 54]
number_list2 = [55, 80, 72, 35, 60, 123, 54, 29, 91]
unique_numbers = []
seen = set()
for number in number_list1 + number_list2:
    if number not in seen:
        seen.add(number)
        unique_numbers.append(number)
print(unique_numbers)

此版保留首次出现顺序，不修改两个原列表。不能直接拿set输出代替要求保序的结果；输入若含列表等不可哈希元素，也不能直接套此方案。

效率与复习

原去重方法清楚且适用于可比较相等的普通元素，但大输入可能反复扫描；是否改用set辅助取决于数据可哈希性与顺序要求。推导式与普通循环都要遍历输入，不凭写法简短就认定算法提速。列表平方结果若要全部保存，本身需要与结果项数成比例的内存。未做耗时基准。

复习：练习1只调用set后直接print是否满足“排序后输出”？答案：不能保证；还需sorted或列表sort。

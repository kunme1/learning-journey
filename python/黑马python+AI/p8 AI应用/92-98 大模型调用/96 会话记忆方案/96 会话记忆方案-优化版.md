**图片文字版（来源：image.png）：**

Apifox单轮请求：
```json
{
  "model": "deepseek-flash",
  "messages": [
    {
      "role": "system",
      "content": "你是一名非常可爱的AI助理，你的名字叫小甜甜，请你使用温柔可爱的语气回答用户的问题。"
    },
    {
      "role": "user",
      "content": "我现在有12个苹果，3个人，怎么均分？"
    }
  ],
  "thinking": {
    "type": "enabled"
  },
  "reasoning_effort": "high",
  "stream": false
}
```

可见200，回答12÷3=4，每人4个苹果。返回choices[0].message.content与reasoning_content；usage=输入65、输出120、总185，reasoning_tokens=46。生成文本的修辞省略，算式和字段保留；这些是图中结果，不是本批新请求。

现状关系图：第一请求system＋“12个苹果3人”→assistant答每人4；第二请求仅system＋“那2个人呢”→assistant要求补上下文。图中文字将接口交互概括为无状态；本课Chat Completions需要应用携带历史，不推广成所有服务绝不保存数据。

![原图 image-3.png](<image-3.png>)

**图片文字版（来源：image-3.png）：**

滚雪球图按顺序：system→user(12个苹果3人)→assistant(每人4)→user(2人呢)→assistant(每人6)→user(4人呢)，得到每人3。结构转写（为省略模型冗长修辞，回答用同义算式压缩，role和顺序保留）：
```json
{
  "messages": [
    {
      "role": "system",
      "content": "你是一名非常可爱的AI助理，你的名字叫小甜甜，请你使用温柔可爱的语气回答用户的问题。"
    },
    {
      "role": "user",
      "content": "我现在有12个苹果，3个人，怎么均分？"
    },
    {
      "role": "assistant",
      "content": "12个苹果分给3个人，每个人4个。"
    },
    {
      "role": "user",
      "content": "那两个人呢？"
    },
    {
      "role": "assistant",
      "content": "12÷2=6，每人6个。"
    },
    {
      "role": "user",
      "content": "那4个人呢？"
    }
  ]
}
```



**补充（参考课程资料）：**保留角色和时序；每轮历史越长，输入token、延迟和上下文占用可能增加。可在产品中做摘要／窗口，但会丢部分信息，不把截断当无损优化。JSON用true，Python字典用True；流式需对应迭代解析，不只是改一个布尔后仍当整包读取。

**图片文字版（来源：image-4.png）：**

Apifox将两轮user与assistant历史一起放进messages，再追问“6个人呢”；顶层仍model=deepseek-flash、thinking.enabled、reasoning_effort=high、stream=false。图中回答12÷6=2；usage输入205、输出115、总320。截图还把reasoning_content放进旧assistant对象，本课无tools场景通常无需回传该思考字段；当前官方说明以具体接口／工具上下文为准，不能推广为所有调用都删除思考字段。原笔记随后“流式输出，stream改true”指JSON小写true。

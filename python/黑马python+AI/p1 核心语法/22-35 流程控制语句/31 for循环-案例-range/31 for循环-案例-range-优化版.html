对照当前前半段代码

# 案例1

# 1-2求和，1-100无法使用
i = 1
total = 0

for i in (1, 2):
    total += i
    i += 1
print(total)

# 求1-100所有奇数的和

total2 = 0
for j in range(1, 101, 2):
    total2 += j
print(total2)

执行解释：第7行遍历元组(1,2)，只取得1和2，所以第一段打印3；它并不是1—100奇数求和的实现。第15行range(1,101,2)依次给出1、3、…99，total2累加后打印2500，已完成第一项题目。

【可读性改进】第4行 i = 1 被for首次取值覆盖，第9行 i += 1 不影响下一轮取值，本脚本后面也不读取i，可删除。第25行 k += 3 同样不能让range跳过后续整数；下一轮k仍由迭代器赋值。这里删除不改变三条输出，但会改变循环结束后变量i/k的最终值，未来如果读取它们需重新评估。

【纠正】第3行“1—100无法使用”应限定为“当前(1,2)只有两项”；不是for不能处理1—100。不要把C的for三段式中手工更新循环变量的习惯直接套用在Python for上。

range 的三种形式

图片文字版（来源：image-4.png）：

形式 课件含义 例子与序列
range(end) 从0开始，不含end range(5)：0、1、2、3、4
range(start,end) 从start开始，不含end range(2,8)：2、3、4、5、6、7
range(start,end,step) 按step步进，不含end range(0,10,2)：0、2、4、6、8

补充：range返回range对象，按需要表示整数序列，不会先生成完整列表。步长不能为0；负步长可以倒序，例如 range(5, 0, -1) 得到5至1。range(1,101,2)最后一个值是99。

3的倍数：原实现与减少重复工作的写法

# 100-500 间 3 的倍数之和

total2 = 0
for k in range(100, 501):
    if k % 3 == 0:
        total2 += k
        k += 3
print(total2)

原实现检查100—500的401个整数，仅把能被3整除的数相加，实际输出39900。

前瞻优化：100之后第一个3的倍数是102，直接步进3可省去逐项取模，也不需要手动改变k。下例完整可运行，输出2500和39900；它省略了原文件开头用于演示的输出3，因此与整个原脚本相比少一条输出。

odd_total = 0
for number in range(1, 101, 2):
    odd_total += number
print(odd_total)

multiple_of_three_total = 0
for number in range(102, 501, 3):
    multiple_of_three_total += number
print(multiple_of_three_total)

已知规律时也可 print(sum(range(102, 501, 3)))，sum执行累加；这会隐藏累加器过程，保留原循环有教学价值。减少的是遍历次数（401→133），没有做耗时基准，不把“行数少”当作提速证据。

### 电商订单计算器

![原图 image.png](<image.png>)

**图片文字版（来源：image.png）：**

传入多件商品（名称、价格、数量）、优惠券、积分、运费计算总金额。优惠券：商品金额满5000，券额不得超过商品总价；积分：商品总金额满5000，每100积分抵1元，仅整百，抵扣不得超过商品总价。

数据用*args接收，coupon/score/express在*args后只能关键字传入。积分score是合法词但points更具体；express作为运费可读性弱于shipping_fee，保留原接口不破坏关键字调用。原总价列表可改sum(price * quantity for name, price, quantity in args)，解包明确字段，省临时列表。**规则口径待确认：**原.py及P70逐字稿都先扣券，再用余额>=5000判断积分；题面也可理解为均按优惠前金额。优化版默认保留课程顺序，另定义by_subtotal对照，不擅自将其中一种标为唯一正确。5000、券10、积分4000的两版分别4990与4950，已运行验证；本批三个原样例不触及此分歧。

**对应原始代码片段（保留注释状态）：**

```python
"""
案例2：定义一个用于根据传入的一批商品信息（商品名、价格、数量）、优惠（优惠券、积分抵扣）、运费信息计算订单的总金额的函数。

具体规则如下：
    1. 优惠券需要商品金额满5000才可以使用，且优惠券金额不能超过商品总价。
    2. 积分抵扣需要商品总金额满5000才可以使用，100积分抵扣1元（且抵扣金额不能超过商品总价，积分只能整百抵扣）。
"""

def calc_order_cost(*args, coupon = 0, score = 0, express = 0.0):
    """
    根据传入的一批商品信息（商品名、价格、数量）、优惠（优惠券、积分抵扣）、运费信息计算订单的总金额

    :param args: 商品信息（商品名、价格、数量） ---> 如：（"鼠标", 188, 2）（"键盘", 388, 1）
    :param coupon: 优惠券
    :param score: 积分
    :param express: 运费
    :return: 订单的总金额
    """

    # 订单的总金额 = 商品总金额 - 优惠券 - 积分抵扣 + 运费

    # 1. 计算商品总金额
    total_price = [goods[1] * goods[2] for goods in args]
    total_cost = sum(total_price)

    # 2. 加载优惠券
    if total_cost >=5000 and total_cost >= coupon:
        total_cost -= coupon

    # 3. 加载积分抵扣
    if total_cost >= 5000 and score // 100 <= total_cost:
        total_cost -= score // 100 

    # 4. 添加运费
    total_cost += express

    return total_cost

# 测试
total = calc_order_cost(("鼠标", 188, 2), ("键盘", 388, 1), ("手机", 3999, 1), coupon=10, score=4000, express=9.9)
print(total)

total = calc_order_cost(("鼠标", 188, 2), ("键盘", 388, 1), ("手机", 6999, 1), coupon=10, score=4000, express=9.9)
print(total)
total = calc_order_cost(("鼠标", 188, 2), ("键盘", 388, 1), ("手机", 6999, 1), express=9.9)
print(total)
```

生成器由sum逐项消费，不保留金额列表；主函数保持课程先券后积分的余额判断，另一个函数演示按原价判断。假定金额有限非负、积分为非负整数；不把该小例声称为完整金额精度或生产结算系统。

# 同步原文件本轮默认值0→0.0；未传运费且总价全为整数时，返回值由int变float，数值不变。
def calc_order_cost(*args, coupon=0, score=0, express=0.0):
    """沿用课程顺序：扣券后余额再判断积分门槛；假定数值有限、非负，积分为整数。"""
    # 原先先建商品金额列表再sum；sum消费生成器，省去临时金额列表。
    # 解包使price/quantity含义明确。只改变表达式，保留课程扣减顺序与金额结果。
    total_cost = sum(price * quantity for name, price, quantity in args)
    if total_cost >= 5000 and coupon <= total_cost:
        total_cost -= coupon
    points_discount = score // 100  # 原重复score//100，命名说明单位是元而非积分。
    if total_cost >= 5000 and points_discount <= total_cost:
        total_cost -= points_discount
    return total_cost + express


def calc_order_cost_by_subtotal(*args, coupon=0, score=0, express=0.0):
    """前瞻口径示例：两次资格均按优惠前金额判断，不自动取代课程版本。"""
    # 行为变化：原价5000、券10、积分4000时，此版4950；课程顺序版4990。
    # 同时防止叠加抵扣为负：只有本次抵扣不超过当前余额才使用，与原“超额不使用”一致。
    subtotal = sum(price * quantity for name, price, quantity in args)
    remaining = subtotal
    if subtotal >= 5000 and coupon <= remaining:
        remaining -= coupon
    points_discount = score // 100
    if subtotal >= 5000 and points_discount <= remaining:
        remaining -= points_discount
    return remaining + express
